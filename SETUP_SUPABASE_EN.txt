--------------------------------------------------------------------
  ABOUT PATCH 1
  SQL Editor -> New query -> paste ALL of supabase_parche1.sql -> RUN
  It should finish with:  OK · create_fuel_po lista

  WHY: the phone has to save the PO and get the number back. A normal
  INSERT that returns the row requires READ permission on the table, and
  the field must NEVER be able to read the registry. This function does
  both safely: it saves the row and returns only the PO number.

  It also moves three checks into the database itself, where nobody can
  get around them:
    - the vehicle must exist in the fleet
    - the jobsite must be a real jobsite (a contract number is refused)
    - the odometer/hours cannot go backwards
  And it is idempotent: if a phone retries, it gets the SAME PO back
  instead of creating a duplicate.

       Under "Publishable key", row "default", click the copy icon.

====================================================================
  VERSION NUMBERS - HOW TO READ THEM
====================================================================
  Do NOT hand-edit version numbers. There are three, each in its own
  file, and I bump them when I change that file:

    v7.4  -> lives in app.js. Prints at the bottom of the NAMES screen
             of the orders app (index.html). If you only uploaded
             fuel.js/fuel.css/sw.js, this correctly stays at 7.4 -
             app.js did not change.
    v2.1  -> lives in fuel.js. Prints on the fuel "PO registrado" screen.
    v42   -> the cache name inside sw.js. Not shown anywhere; it is what
             forces phones to pick up new files.

  IF A PHONE STILL SHOWS OLD BEHAVIOR AFTER YOU UPLOAD:
    The app is a PWA - the service worker serves the cached copy until
    the new one takes over. To force it:
      iPhone: close the tab AND swipe the app closed, then reopen.
               (Or Settings > Safari > Advanced > Website Data > remove
                muniz-2026.github.io)
      Installed to home screen: swipe it closed and reopen twice.
    GitHub Pages also takes 1-2 minutes to publish after a commit.
    The reliable check is not the version number - it is behavior:
    tap a name and see if the VEHICLE LIST appears. That list only
    comes from the database.
